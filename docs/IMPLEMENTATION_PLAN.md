## Required approvals before state-changing integrations

- **Server/Database:** enabling either is one-way. Managed database is shared across development and published runtime. Obtain explicit owner confirmation before enabling or migrating.
- **LLM provider:** provider/cost/data-processing choice must be explicit; no user health text is sent until approved.
- **Privacy:** history, consent default, retention, deletion/export, session length, reviewers/admin roles and data residency must be approved before persistence.
- **Launch:** qualified clinical review, native-language review, regional numbers, security/privacy, evaluation/operations gates and explicit publication approval.

## Project structure

- `client/src/pages/` — user flows and screens; no medical inference in components.
- `client/src/lib/` — locales, shared schemas, deterministic rule logic and client-safe helpers.
- `shared/` — runtime-validated API contracts, question IDs and public types.
- `server/` — OAuth-backed procedures, provider adapter, rule/classifier pipeline, ownership-checked persistence, health route.
- `drizzle/` — additive schema and migration history only after approval.
- `content/guidance/` — immutable versioned card source, default all draft.
- `research/guidelines/` — source-cited research notes for 23 coverage topics.
- `evaluation/` — provenance and status-tagged vignettes, metric code and report templates; no user PHI.
- root Markdown documents — product, UX, architecture, data/API, agent rules, sequence, and progress.
